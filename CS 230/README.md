Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

The Gaming Room client is the customer that is looking to produce a game application called Draw it or Lose it, they wanted to a layout of the design for the software looking at various aspects such as an object oriented approach, a comparison of different operating systems, system requirements, design constraints, and a recommmendation. They wanted the system to be scalable so that it could expand and have a solid infastructure to run the system.

What did you do particularly well in developing this documentation?

I did a good job breaking down the model into an object oriented approach, it was easier for me to look ath the UML diagram and describe how each of these attributes or functions work together and interact as a system. I also enjoyed the recommendation section as it required using all of the data we had gathered and a little bit more to pull it all together for the best recommendation for the system.

What about the process of working through a design document did you find helpful when developing the code?

I found looking at the UML object model and translating into a narrative on how the code works together to be the most helpful part of the document, This made it easy to see how the code should function as a whole which made it easier to turn into workable code.

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If there was one part I would choose to go back and revise the work that i did on it would probably be the section where we compared the different operating systems from the server side, client side, and the languages used. I would pick this because I feel I could've looked deeper into each of the operating platforms and the specifics of them, I feel I was just barely scratching the surface in my studies.

As someone who has played many different typoes of gamming application, I would say that I keep the user's needs in mind by putting myself in there shoes and build something that I would want to use. It is important to consider the user because the are going to be the ones using the system, without them the system would fail and they wouldn't have a product they enjoy.
